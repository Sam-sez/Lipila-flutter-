# Lipila architecture notes

## What this is

Mobile-payments Flutter app, Android only. Three payment paths:
- **QR scan** — camera reads a static or dynamic QR code
- **Favourites** — tap a saved contact
- **Bong** — proximity payment via BLE (the one that doesn't work yet)

Backend: FastAPI on Vercel + Neon + Upstash. Base URL: `https://lipila.vercel.app/api`.
No backend changes are in scope for the current debugging work.

## android/ is not committed

`android/` is generated by CI (`flutter create`) on every push and patched by
`tool/patch_manifest.py`. Never commit `android/` without explicit owner agreement.
Never run `flutter create .` in the repo root — it will clobber `lib/` and `pubspec.yaml`.

To build locally, generate `android/` into a temp dir first:
```
flutter create --platforms=android --org com.lipila --project-name lipila C:\Temp\scaffold
Copy-Item -Recurse C:\Temp\scaffold\android .\android
python tool/patch_manifest.py
flutter pub get
flutter build apk --debug  --dart-define=API_BASE_URL=https://lipila.vercel.app/api --dart-define=BUILD_ID=local
flutter build apk --release --dart-define=API_BASE_URL=https://lipila.vercel.app/api --dart-define=BUILD_ID=local
```

## BLE plugins

Two are needed because no single Flutter plugin does both roles reliably:
- `flutter_blue_plus ^1.34.5` — central role (scan for nearby devices)
- `flutter_ble_peripheral ^1.2.6` — peripheral role (advertise this device)

API notes for these specific versions:
- `AdvertisementData.serviceUuids` is `List<Guid>` (changed from `List<String>` at 1.28.0). `.toString()` on a Guid returns the UUID string.
- Use `FlutterBluePlus.scanResults` for continuous 60-s scan (keeps previous results). Use `onScanResults` if you want a clean slate each scan cycle.
- `AdvertiseData(serviceUuid: token, includeDeviceName: false)` is correct for flutter_ble_peripheral 1.2.6.

## Permission setup

See HANDOVER.md section 5 for the full analysis. Short version:
- Android 12+ (SDK 31+): BLUETOOTH_ADVERTISE, BLUETOOTH_SCAN (neverForLocation), BLUETOOTH_CONNECT. No location needed.
- Android ≤ 11 (SDK ≤ 30): also needs ACCESS_FINE_LOCATION + device Location switch on.
- The code currently requests `locationWhenInUse` on all SDK levels — this is hypothesis H1 (may cause failure on SDK 31 if location isn't in the manifest). The diagnostics log will confirm.
